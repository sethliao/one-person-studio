# 通用大脑：把任意 Markdown 文件夹，变成所有 Agent 的记忆

> 一套跑了一整季动画生产的「AI 大脑」约定。不装数据库、不锁平台、人随时能读——因为大脑的格式，比大脑的智能更长寿。

## 它解决什么问题

你的 AI 助手每次醒来都是新的。项目背景、角色设定、踩过的坑、做过的决定——**每次会话都要重新解释一遍**，解释到第 10 次你就会放弃，回到「什么都记不住」的状态。

市面上的解法是记忆层产品：向量数据库（Mem0）、记忆分页（Letta）、时序图谱（Zep）。它们很强，但有一个共同的代价——**记忆格式人读不了、搬不走**。你的记忆被锁在某个 vendor 的 embedding 里，换一个 agent，记忆就留在原地了。

这条管线选了相反的路：**记忆就是一个 Markdown 文件夹**。Obsidian 能开、VS Code 能开、任何 agent 都能读、git 能管、20 年后还能打开。

## 三个信条

1. **大脑要人能读，agent 才能用得久。** 记不住的原因通常不是 agent 太笨，是笔记结构人自己都不想看。人愿意维护的结构，agent 才有得读。
2. **同一个事实只能有一个真源。** 背景信息、决策记录、操作日志各归各层，改一处就够了。两处可写 = 必然打架。
3. **记忆要分层瘦身，不是越攒越多。** 每层的容量有上限，超了就蒸馏下沉——细节指向文档，指针留在记忆里。

## 三层架构

```text
会话 / 收藏 / 项目日常
        │
        ▼
┌─────────────────────────────────────────┐
│ ① 入口层 —— 000- 开头的「现在做什么」页    │  ← 全库唯一入口，回答「现在做哪件」
│    aliases 用口语词命名，搜「验收」就能找到 │
├─────────────────────────────────────────┤
│ ② 记忆层 —— 三层分存                      │
│    machine/ 每日工作日志（append-only）    │
│    human/   人读结论与决策                │
│    global/  跨项目铁律（≤3KB 指针版）      │
├─────────────────────────────────────────┤
│ ③ 链路层 —— chains/REGISTRY.md           │
│    链 = skills 的使用单位：               │
│    口令 → 按序调用 → 文件交接 → 门控       │
└─────────────────────────────────────────┘
        │
        ▼
任何 agent 都能接：WorkBuddy / Claude Code /
Codex / 豆包 / Cursor —— 读同一套文件
```

### ① 入口层：一页 answering「现在做什么」

一个文件夹要成为大脑，先要有一页**唯一的入口**：项目到哪了、下一步做什么、去哪找东西。约定：

- 文件名以 `000-` 开头（列表置顶，永远不会沉底）
- 这一页只做导航和状态，不装细节——细节在各条线的文件里
- **aliases 必须用你的口语词**：你嘴上叫「验收包」，文件就叫「验收包」，别叫「acceptance-report-v2-final」。找不到的大脑等于没有大脑。

### ② 记忆层：分存，且都小

| 层 | 放什么 | 纪律 |
|---|---|---|
| `machine/` 每日日志 | 今天跑了什么、改了什么文件 | **append-only**，只增不改；临时输出（搜索结果、报错）不进 |
| `human/` 结论与决策 | 值得人读的结论、带原话的决策记录 | 一条决策一页，写完不改，新结论新开一节 |
| `global/` 跨项目记忆 | 铁律、判据、口味 | **指针化**：上限 3KB，只留指针和铁律，细节指向文档 |

### ③ 链路层：skills 怎么串成链

单 skill 解决单工序，**链解决整件事**。一个链注册表记四件事：

```markdown
## 链：从收藏到实测
口令：「跑一条」
步骤：x-bookmarks-mining → new-tool-triage → 真做一件 → 台账
交接：上一个 skill 的输出文件 = 下一个的输入，落在同一个 run 目录
门控：triage 判「不值得做」→ 链在此停止，不烧后面的工时
```

链的好处：会话之间靠文件交接（不靠聊天记录），门控让烂任务提前死掉，换一个 agent 也能按注册表跑同一条链。

## 实战纪律（每条都付过学费）

1. **只增量，不重写。** 多个会话（或多个 agent）同时写同一个库时，各写各的文件，全局页只追加。重写 = 抹掉别人的会话记录。
2. **别把记忆养成第二份聊天记录。** 搜索结果、报错栈、临时路径不进记忆；只留跨会话有用的结论。
3. **交接给「读不了你磁盘」的平台。** 有些平台（网页版 Coze / Kimi / GPTs）根本碰不到你的本地文件——用交接包思路把 vault 编译成平台中立的打包页，一次导出，处处能喂。本仓库的 `ai-handover-pack` 就是干这个的。
4. **入口页要「找得到、点得动」。** 链接不包代码反引号；新页面必带 aliases；文件名用你会搜的词。

## 和其他方案的对比

| | **Markdown 大脑（本仓库）** | Mem0 / Letta / Zep（记忆层） | Notion 类 SaaS |
|---|---|---|---|
| 格式 | 纯 Markdown，人直接读 | 向量 / 状态块 / 图谱，需工具才能看 | 私有云端 |
| 归属 | **你的磁盘，你的 git** | 自托管可以，托管在它们手里 | 在平台手里 |
| 换 agent | 任何 agent 都能读 | 各自 API / MCP 生态 | 导出受限 |
| 记忆质量 | 靠结构和纪律 | 自动抽取 + 检索很强 | 靠搜索 |
| 适合 | 个人创作者、长期项目、跨平台工作流 | 生产级多用户产品 | 团队协作 |

坦白说：记忆层产品的**检索**比纯 Markdown 强（向量搜索、时序图谱是真本事）。这个方案赌的是另一件事——**个人的大脑，贵在可维护和可迁移，不在检索精度**；需要强检索时，Markdown 文件夹照样可以喂给任何 RAG（每一条都是干净语料）。

## 10 分钟搭一个最小大脑

1. 建一个文件夹，丢进 `000-现在做什么.md`（结构抄本仓库 `docs/` 里给的开局模板）
2. 建三个目录：`machine/`、`human/`、`global/`，各放一个说明文件
3. 在入口页写三节：**现在做哪件 / 到哪了 / 去哪找**
4. 把这个文件夹的路径告诉你的 agent：「以后每次开工先读它，收工往 machine/ 追加日志」
5. 有了 3 个以上常用 skills 后，加 `chains/REGISTRY.md` 把它们串成链

不想手动搭：装好本仓库后对 agent 说 `/ops-universal-brain`，它会问你三个问题然后自动生成这套骨架。
