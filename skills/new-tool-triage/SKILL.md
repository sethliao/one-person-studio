## 什么时候必须走这套

只要我准备说出下面任何一句，**先说清落到哪一种处置、为什么**：

- 「把它 fork 过来改」
- 「把它的规则抄进我们的脚本」
- 「装一下试试」/「挂上去」
- 「这个我们自己做一份」

## 三步（不能跳）

1. **分清三件事** —— 用户是在「用它」、还是「在它上面加东西」、还是「把它的东西变成我们的」。
   ⚠️ **「我想加规则」≠「我要 fork」。**
2. **查它有没有官方扩展机制** —— 翻 `docs/` `plugin/` `crates/` `contributing`；
   有机制就先走机制。**然后才问值不值**（它的扩展机制是什么语言？我要写多少？）。
3. **落到四种处置之一**，写进结论的一行里：
   - ① **只用** —— 一次性；记进 `CLI-能力登记`
   - ② **扩展** —— 用它的官方插件机制，不 fork
   - ③ **包装** —— 写我们的 wrapper + 锁版本，不 fork
   - ④ **抄** —— 提炼进自己的代码，**必加署名头**

**只有两种情况才 fork**：改动在它内部、提不成 PR；或提了 PR 上游不收/不维护了。

## 顺手必做的两件

- **查许可证**：抄/衍生 = 硬义务。Apache-2.0 → 保留版权 + LICENSE + **标明改了什么**。
  文件头三行模板：
  ```
  # 部分规则提炼自 <owner>/<repo> v<版本> (<许可证>)
  # <URL> · 快照日期 YYYY-MM-DD
  # 改动：<逐条写>
  ```
- **登记进 `System/CLI-能力登记.md`**：① 属哪组 ② **什么场景我会主动想起它**（最重要）③ 实测数字；坑补进「三、实测踩到的坑」。

## 别踩的三个坑（都实测过）

- ⚠️ **别给「二选一」的假选项**。2026-09-24 我看 impeccable 时只给了「抄 or 别用」，
  漏了它 `crates/foundation/rule_pack.rs` 里写明的「adds rules of its own **without forking it**」。
  → **先翻它的扩展机制，再下结论。**
- ⚠️ **Fork 是负债不是成就**。一个 fork = 永久跟着上游 rebase 的代码。默认答案是不 fork。
- ⚠️⚠️ **推荐之前，必须读到它的「安装 / 依赖 / 环境要求」那一段**。2026-09-24 实锤：
  我看到两个仓库的 description 都写着 Omni Flash / HyperFrames，就并排推荐成「跟你的栈严丝合缝」——
  **那是没读 README 的判断**。真读完才发现一个要**自己的 `GEMINI_API_KEY`（= 又一个新付费账号）**，
  且关键步骤依赖 Codex 内置工具；另一个才是零依赖。
  → **判据：你的栈里有同名组件 ≠ 你能直接用它。**
  必须核这三项：① 要不要**新的账号 / API key / 付费** ② 依赖是不是你**已装的版本**（注意版本号！）
  ③ 有没有绑定**别的 harness 的内置工具**。

## 回答「我要不要也开一个 GitHub」时

判据是**「别人能不能用」**，不是「我做得好不好」。
- ❌ vault 整体不可开源（含 IP 设定 / 财务 / 账号数据）
- ✅ 候选物是**能剥离出来的小工具**（例：中文语境 AI 设计指纹 —— impeccable 的 61 条规则一条都没覆盖中文）
- **开源前必须先和 vault 解耦**（硬编码库路径 / 本机字体路径都要去掉）
