# B2B 锚定式合作提案

> 目标：**不把自己放进买家的比价清单，放进对方的方案清单。**
> 方法论原页（vault）→ `Wiki/ToB服务化-锚定框架.md`

## ⛔ 四条铁律

1. **不锚「我要合作」** —— 对方会回「你想要什么」。要锚**一个具体成品**。
2. **不并列多个身份** —— 「参赛者 + 服务商 + 翻译」并列 = 锚不住。**只报一个主身份**，其余降为能力证明。
3. **不卖工时/人力** —— 卖「他们内部造不出来的那一样东西」。
4. **不先问门票/价格** —— 先给成品，再谈身份由对方给。

## 流程

### Step 1 · 实查（不许凭印象）

必查四项，缺一项就停下：

| 查什么 | 怎么查 |
|---|---|
| **决策链** | 官网 → 谁主办/承办/联合发起 → 主办方是哪家公司 → 找「能拍板的人」而不是「对的人」 |
| **议程里的付费位** | 官网 schedule 页 → 哪些工作坊/专场有**外部公司的架构师** → **这就是付费证据** |
| **票档与定价** | 官网 / 票务平台 → 粗估票务盘子（票价 × 目标人数） |
| **社区组织结构** | 搜主办方官网/新闻稿 → 是否有 Workshop / Conference / Fellowship 之类支柱，**哪一条最冷门** |

⚠️ **预算是行业基准，不是对方的账** —— 必须写明这一点，否则会被拆穿。

### Step 2 · 钱的地图

按会议行业基准分三档：

| 档 | 内容 | 可否切入 |
|---|---|---|
| 碰不到 | 餐饮 20–40% / 场地 5–25% / AV 10–25% | ❌ 刚性、不可谈判 |
| 可分包 | **营销宣发 3–15%** | ✅ 软预算，缺口大 |
| ⭐ 主战场 | **赞助商的内容/市场预算** | ✅ **独立于主办方账本，决策快、不走采购** |

⭐ **核心判断**：赞助商付的不是「参会费」，是「开发者/用户心智」→ 这笔预算形态是 **DevRel / 市场**，正是创作者能切的口子。**打赞助商，不打主办方采购。**

### Step 3 · 四层可卖（先判自己在哪层）

| 层 | 是什么 | 判定 |
|---|---|---|
| L0 | 志愿者 / 作品集换曝光 | ⛔ 定价 0，人过剩 |
| L1 | 摄影 / 摄像 / 剪辑 | ⛔ 压价战场，打不过免费 + 官方摄影包 |
| **L2** | **解释层**：把技术/产品讲成第三方能看懂、能传播的内容（拆解/评测/对比/双语） | ✅ **护城河** |
| **L3** | **方案层**：展位叙事 + 讲者排程 + 内容包 + 引流转化 | ✅ **主战场** |
| L4 | 翻译 / 地接 / 行政对接 | 🎫 **只当入场券**，体量小、是苦活不是护城河 |
| 下一层 | **数据服务**（行业行为画像） | ⭐ 唯一真护城河 |

> ⚠️ **常见误判**：把自己定位成「摄影/翻译」→ 掉进 L1/L4，被拿去比价。
> **L1/L4 都是苦活**，护城河在 L2/L3。

### Step 4 · 定锚定身份（只一个）

选标准 = **硬凭证 + 稀缺能力 + 内行视角** 三者同时具备。
只报主身份，其余全部降为「为什么是我」的支撑材料。

### Step 5 · 产出：N 页方案 + 5 行附言

⛔ **不要先写邮件正文**。理由：**方案本身就是锚**。
- 一封信 → 只能被回「你想要什么」
- 一份具体方案 → 只能被回「这个我们讨论一下」

方案页固定结构（Google Slides / PDF / HTML 均可）：

| 页 | 内容 |
|---|---|
| 1 | 一句话锚：10/16 那天，2000 人进场时看到的那套内容，我来做 |
| 2–4 | **三件具体成品**（点名、带数量、观众看完能带走什么） |
| 5 | 为什么是我（三条凭证，不吹） |
| 6 | 报价 / 合作方式（这一页放最后，附件才成立） |

附言 5 行：`附件 6 页，先给您看 / 一句话我是谁 / 三件成品 / 凭证链接 / 我用 Gmail 发`

⛔ 全文**不提门票、不提价格、不提志愿者通道**。

#### 制作配方（2026-10-04 GOSIM 实跑验证）

1. **格式**：HTML（1920×1080 页，走 vault `DESIGN.md` token）→ Chrome 无头出 PDF（邮件附件）。
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --no-sandbox --disable-gpu \
     --no-pdf-header-footer --print-to-pdf=out.pdf "file://$PWD/index.html"
   ```
   CSS 要点：`@page{size:1920px 1080px;margin:0}` + `.page{width:1920px;height:1080px;page-break-after:always}`。
   ⚠️ 本机 Chrome 沙箱必挂，`--no-sandbox` 必加。
2. **验收看图**：`--screenshot --window-size=1920,6900` 出整页长图 → PIL 按 stride（1080+gap）切片逐页看，**别只看缩略图**。
3. **实踩两个坑**：① 页容器忘写 padding → 内容全贴边（截图立刻可见）② 封面页脚用 absolute 定位会压到压暗带内容 → **封面不放页脚**。
4. 出图后跑 `design_audit.py` 到 0（见 design-codex skill）。
5. 案例成品：`003-Workbench/gosim-proposal-2026-10/`（可直接抄骨架）。

### Step 6 · 五个出口（串联的答案）

一场现场必须同时开五个口，否则报价天花板被锁死：

```
① 交付物(报价)  ② 内容(个人IP)  ③ 素材库(可复用/卖展商)
④ 关系(讲师/赞助商/媒体)  ⑤ 数据(行为画像)
        ↓
   案例与背书 → 下次报价更高
```

⭐ **提案/邮件不是第六件事，是这五个出口的启动器。**
只服务①②的提案 = 把自己框成摄影。

## 反面清单

- ❌ 先问门票 / 学生票
- ❌ 「我可以做 A/B/C」能力清单
- ❌ 报价菜单（把对话拉回「你多少钱」，正是要避开的锚）
- ❌ 并列多个身份
- ❌ 把自己写成「摄影师 + 翻译 + 志愿者」
- ❌ 结尾问「能聊聊吗」（把决策压给对方）
- ❌ 拿行业预算当对方实际账目

## 检查清单（发送前）

- [ ] 四项实查都做了，链接可点
- [ ] 预算数字标注了「行业基准，非对方账目」
- [ ] 议程页有付费位的证据（外部公司架构师）
- [ ] 主身份只有一个
- [ ] 全文搜「门票」「价格」「报价」「元」→ 应为零命中
- [ ] 三件成品是具体名词，不是形容词
- [ ] 附件存在，链接能打开
- [ ] ⛔ 已交用户过目，**没有代发**
