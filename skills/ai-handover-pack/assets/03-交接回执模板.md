# 交接回执模板

> **用途**：外部 AI（扣子 / Kimi / 豆包…）干完活后，按这个格式回填一份，
> WorkBuddy 就能直接把产出落进 vault，不需要 Seth 再复述一遍。
>
> 用法：把这段模板作为「输出格式要求」写进外部平台的提示词末尾。

---

## 模板（复制这段给外部 AI）

```markdown
# 交接回执 · {{日期}} · {{任务名}}

## 1. 任务
（一句话：这次做了什么）

## 2. 产出物
| 类型 | 名称/链接 | 说明 |
|------|-----------|------|
| 分镜 | … | … |
| 图 | … | … |
| 视频 | … | … |
| 文案 | … | … |

## 3. 关键参数
- 用的模型：
- 画幅 / 分辨率：
- 消耗（积分 / 金额）：
- 是否用了参考图：

## 4. 与原设定的偏差
（哪里没做到。没有就写「无」。**不要隐瞒失败**——写清楚我才知道要不要重跑。）

## 5. 待 WorkBuddy 入库
- [ ] 成片 → `Assets/小厚先生/generated/`
- [ ] 分镜 → `001-Projects/小厚先生/内容产出/`
- [ ] 提示词 → `Wiki/小厚先生/` 或 Plan 附件
- [ ] 结论沉淀 → `HermesBrain/Memory/Decisions/`

## 6. 链接清单
（按行写纯链接，方便批量下载）
```

---

## 为什么必须走这个格式

三个理由，缺一不可：

1. **落库不用问** — 我知道东西该进 `Assets/` 还是 `Wiki/`，不用 Seth 重新解释一遍
2. **失败留痕** — 「第 3 镜角色漂移了，重跑 2 次」这种信息比成片本身更值钱
3. **成本可追踪** — 攒够几份回执，就能算出「一条片子真实成本」，这是 Seth 关心的数字

---

## 回流后的处理（WorkBuddy 侧）

拿到回执 → 我按这个顺序做：

1. 下载链接里的媒体 → `Assets/<IP>/generated/`（二进制只进 Assets，笔记里只放双链引用）
2. 分镜/提示词 → `001-Projects/<IP>/内容产出/`
3. 更新 `000-下一件事.md` 的「📌 现在到哪了」
4. 有可复用结论 → `HermesBrain/Memory/Decisions/`
5. 成本数据 → 汇总进三 IP 算总账的表
